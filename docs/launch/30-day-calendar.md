# 30-Day Promotion Calendar

External posts are drafts until owner approves platform, account, exact copy,
destination, and timing. Do not publish automatically.

| Days | Focus | Deliverable | Status |
|---|---|---|---|
| 1–2 | Foundation | README, quick start, release links, asset capture plan | Complete in repository; screenshots pending real recording |
| 3–4 | Demonstrations | Record three real demos from `demo-guide.md` | Pending owner recording/publishing choice |
| 5–7 | Launch foundation | Review platform-specific drafts; publish only approved posts | Drafted, not published |
| 8–10 | Hacker News | Submit approved Show HN; answer technical questions factually | Drafted, not submitted |
| 11–14 | Reddit | Check current subreddit rules; post only where allowed | Drafted, not submitted |
| 15–18 | Product Hunt | Finalize real screenshots and maker profile; launch after approval | Drafted, not submitted |
| 19–21 | Technical discovery | Publish approved DEV article; share architecture explanation | Drafted, not published |
| 22–24 | Support | Triage real installation/docs reports; update docs through normal PRs | Pending feedback |
| 25–27 | Contributor path | Publish approved tutorial; label real bounded contributor tasks | Pending real tasks |
| 28–30 | Review | Record public GitHub metrics and voluntary feedback; publish factual update | Pending data |

## Weekly review questions

1. Which installation failures are reproducible?
2. Which docs questions repeat?
3. Did any report identify unsafe or misleading behavior?
4. Which real tasks can be labeled for contributors?
5. What evidence supports next public update?
