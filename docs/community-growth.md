# Community Growth Measurement

## Purpose

Measure discoverability, support burden, and voluntary community activity without
tracking users or changing local-first application behavior.

## Metrics

| Metric | Definition | Collection |
|---|---|---|
| Stars and forks | Public GitHub repository totals | GitHub repository Insights or API snapshot |
| Unique contributors | GitHub contributors visible in repository history | GitHub Contributors page; count people, not commits |
| New issues and pull requests | Opened items during reporting period | GitHub Issues and Pull Requests filters |
| Release downloads | Per-asset download counts shown by GitHub Release API | GitHub release asset statistics |
| Documentation feedback | Issues, discussions, or PRs explicitly about docs | Manual issue labels/search |
| Installation failures | Reproducible reports labeled or identified as install/setup | Manual triage; no inferred users |
| Confirmed adoption | Voluntary, attributable public statements or opt-in reports | Link source; never estimate from stars/downloads |

## Cadence

Record baseline after launch, weekly for first 30 days, then monthly. Publish a short
public update only with actual dated values and links to source data. Keep qualitative
feedback separate from numerical metrics.

## Privacy

ZEROAGENT X adds no telemetry, analytics beacon, hidden download tracking, or user
identifier. GitHub supplies aggregate platform metrics under GitHub policy. Never
collect private workspace names, prompts, agent evidence, credentials, or personal
data for growth reporting.

## Limits

Stars, forks, downloads, and page views do not equal active users, security, quality,
or production adoption. Download totals include repeat downloads and automation.
Public contributors can use multiple accounts. Treat all metrics as directional
signals, not benchmarks or guarantees.
